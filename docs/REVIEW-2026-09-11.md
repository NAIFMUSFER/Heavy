## Corrected findings

1. **Stored cart could break the application.** At the baseline, web initialization accepted any parsed JSON; `null`, `{}` and `[null]` each reproduced a render-time exception. Native checked the outer array only and performed overlapping fire-and-forget writes from a React effect. Shared `assets/local-cart.js` / `mobile/local-cart.mjs` now validates complete bounded selections, serializes writes and publishes only persisted state. Failed storage reads retain the original record and expose retry/explicit reset. Failed writes retain previous visible quantities. The account's saved cart and confirmed orders are separate from a device reset.
2. **Cart changes could be lost around asynchronous work.** Both clients now route quantity changes, restored choices and checkout acknowledgement through the persistence controller. Native list/basket additions merge with the current committed selection. Quote creation waits for pending local writes. The existing exact-quote comparison retains later additions. Acknowledging an unchanged cart requires no redundant write.
3. **Monetary entry differed across clients.** Web rejected `١٢٫٣٤` / `۱۲٫۳۴`; native rounded a refund entry of `12.345` into 1235 halalas. Shared input helpers normalize Arabic/Persian digits and the Arabic decimal mark, reject ambiguous grouping/exponents/extra decimal places and convert decimal text to exact safe integer halalas. Native list quantities, ratings and Saudi reminder dates use bounded normalized input. API monetary units and business permissions are unchanged.
4. **Staff account links were broken.** Inventory/finance/support links generated nonexistent individual HTML pages. Their actual shared `/admin.html` workspace is now used; picker/courier keep their dedicated pages and server-side role enforcement.
5. **Native account startup could strand the user after a transient failure.** Cart, account and catalog initialization now complete independently. An account failure exposes a persistent retry action. Supplemental account-data failure after successful login no longer reports the login itself as failed. Session generations prevent superseded restore responses from updating the current account; notification/support reads also ignore ended sessions.
6. **Reference files had stale status.** API overview now includes password rotation, quote recovery/release, maps and recorded courier positions. Architecture distinguishes the implemented Resend adapter from unconfigured channels, and existing image display from pending upload storage. The earlier delivery report is explicitly historical. Public smoke now includes the checkout and new shared modules.
